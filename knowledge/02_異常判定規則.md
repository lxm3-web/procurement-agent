# 02 異常判定規則

## 什麼算異常（detect 用）
`inbox/` 有還沒標 `.done` 的通知信 → 就是一筆待處理異常（Sheet 的 `supplier_notices` 分頁若存在，`status` 不是 done 的列也算）。沒有通知但 `inventory` 裡 `current_stock < safety_stock` 的料號，也列出來提醒，但**不主動處理**，先問人。

## 四個數字（handle 用，每個都要算出來）
| 數字 | 算法 | 來源表 |
|---|---|---|
| 撐幾天 days_remaining | current_stock ÷ daily_usage，無條件捨去 | inventory |
| 需求量 required_qty | 該料號所有訂單 quantity 加總 | production_schedule |
| 備援可供 available_qty | 該料號所有備援供應商 available_qty 加總 | vendors |
| 缺口 shortage | required_qty − available_qty，小於 0 記 0 | 算出來的 |

## 風險等級
- **high**：撐不到 3 天，或任一受影響訂單 priority＝high
- **medium**：低於安全庫存，或延遲超過 7 天
- **low**：其他

## 要誰核准（依風險）
high → 採購主管｜medium → 採購經理｜low → 不用核准，記錄即可

## 觸發的規則要列出來（policy 表）
policy 是 10 條規則重複 5 批，**只看 R001–R010**。逐條對照，符合的列在報告裡；描述後面的「規則批次：n」不要抄。
| 條件 | 意思 |
|---|---|
| price_delta_percent > 5／> 10 | 備援漲幅超過 5%／10% |
| priority = high | 有高優先訂單受影響 |
| days_remaining < 3 | 撐不到 3 天 |
| current_stock < safety_stock | 低於安全庫存 |
| available_qty < required_qty | 備援不夠 |
| delay_days > 7／> 14 | 延遲超過 7／14 天 |
| no_backup_vendor | 沒有備援 |
| customer_priority = strategic | 策略客戶（目前資料沒有這個值，遇到再說） |
